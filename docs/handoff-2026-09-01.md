## Hallazgos, en orden de prioridad

### 1. El filtro de automotoras no existe, y el último commit dice que sí

Commit `3afa7d7 "change main filter to only non-dealership vendors"` — no implementa ningún
filtro. La ÚNICA entrada que llegó a la cola de contacto en la corrida real fue una automotora:
listing `1049705647676534`, "Fiat uno way divino con A/C NOAHCARS‼️‼️‼️".

Prueba directa contra esa publicación:
```json
{ "sellerType": null, "isDealer": false, "make": null, "mileageKm": null }
FLAGS: { "score": 0, "hits": [], "disqualified": false }
```
Su descripción dice literalmente: "Noah Cars", "☑️Venta - Permuta -Financiación☑️",
"Contamos con servicio de escribania y gestoria", "Consulte financiacion".

Hay tres defensas contra revendedores y las tres están inertes:
- `isDealer` se calcula en `src/services/marketplace/detail.mjs:148` y no se lee en ningún lado.
  Además Facebook mandó `vehicle_seller_type: null` en este caso, así que el campo
  estructurado no alcanza como única señal.
- `sellerScore` (`src/services/scoring/scorer.mjs:101`) depende de `sellerActiveCount`, que el
  worker nunca completa. `countActiveBySeller` (`src/db/repo.mjs:219`) es código muerto.
  Nota: el conteo por `seller_id` necesita la base; en dry-run se puede derivar del batch.
- `evaluateFlags` (`src/services/scoring/flags.mjs`) da 0 hits: `/\bpermuto\b/` no matchea
  "Permuta", `/\bfinanciad[oa]\b/` no matchea "Financiación"/"financiacion", y
  `/financiación de la casa/` exige la frase completa.

### 2. El detalle se busca y se tira

El worker abre páginas de detalle (con su costo de rate limit) y no persiste nada.
`upsertListings` (`src/db/repo.mjs`) no escribe `description`, `mileage_km`, `vehicle_year`,
`make`, `model`, `detail_fetched_at`, y no existe ningún `updateDetail`.
`/api/opportunities` selecciona esas columnas y siempre van a venir null.

### 3. `contact_queue` nunca se escribe

La tabla está en `src/db/schema.sql:107`. No hay un solo INSERT en el repo. La cola sale por
`console.log` en `src/worker/sync.mjs` y muere con el proceso.

### 4. El cache de precios de referencia no se usa

`getFreshReference` (`src/db/repo.mjs:147`) y `saveReference` (`:157`) son código muerto.
`reference_prices` siempre vacía. La Fase 3 de `docs/claude-prompt.md` pedía TTL explícito
("no pegarle a la API por cada listing"). Sin cache, MELI recibe una llamada por listing por
corrida (hasta 24). También muertos: `listActiveForScoring` (`:188`), `closePool` (`:28`).

### 5. Higiene de la API (barato y con filtración real)

En `src/main.mjs`:
- No hay `/health`.
- No hay handler 404 → devuelve HTML de Express, no el `{error:{code,message}}` que documenta el README.
- **No hay error handler** → un body JSON malformado devuelve el stack trace completo con
  rutas absolutas del filesystem al cliente. Verificado:
  `curl -X POST -H 'content-type: application/json' -d '{bad' localhost:4000/api/marketplace`

### 6. Dos scrapers, dos Chromium, y el público sin rate limiting

`/api/marketplace` sigue usando el `src/services/scraper.mjs` viejo (504 líneas), con su propio
singleton de browser (`scraper.mjs:76` vs `src/services/marketplace/browser.mjs:20`) y **sin nada
de rate limiting**: ni delay, ni tope de concurrencia, ni presupuesto de sesión. Medido: 3.4s de
respuesta, cero pausa. El README promete 8–20s por navegación; eso solo lo cumple el worker vía
`withPoliteSlot`. Un loop contra ese endpoint le pega a Facebook sin freno.

### 7. La referencia interna está contaminada

Sin credenciales MELI la mediana (7495 en la corrida) sale del mismo batch de Facebook, que
incluye 4 publicaciones de NOAHCARS. La referencia que decide el ranking se construye en parte
con las publicaciones que queremos excluir. Considerar excluir automotoras detectadas del
cálculo de `referenceFromInternal`.

### 8. La única oferta generada fue un no-op

`oferta USD 5990 (pide 5990, mediana 7495, expectativa alta)`. Como el auto ya está bajo la
mediana, `min(mediana*0.82, asking)` en `src/services/scoring/offer.mjs` colapsa al precio
publicado, y el borrador dice "te pago 5990" por algo que sale 5990. Los tests lo cubren como
diseño intencional (`offer never exceeds the asking price`), así que decidir explícitamente:
o se descarta la entrada, o se ofrece un descuento mínimo sobre el publicado.

### 9. No hay scheduler

La Fase 2 pedía "worker programado que corre cada N horas". `npm run worker` es manual.
No hay cron, systemd ni `setInterval`.

### 10. El MCP expone solo la búsqueda vieja

`mcp-server/src/index.ts` expone `search_marketplace`, que apunta al scraper por keyword.
Ni el ranking ni la cola de contacto están expuestos como tools.

### 11. Tests y limpieza

Solo `tests/unit/scorer.test.mjs` y `offer.test.mjs`. Nada para `extract.mjs`, `url.mjs`,
`mapDetail` sobre fixtures, `repo.mjs` ni las rutas. `npm test` hardcodea los dos paths, así que
un archivo de test nuevo no se levanta solo — conviene pasarlo a `node --test tests/unit/`.
Sobró scaffolding de Playwright sin relación (`playwright.config.js`, `tests/example.spec.js`,
`tests-examples/`) y hay dos lockfiles (`bun.lock` + `package-lock.json`).

## Restricciones que no se negocian

- **Nada de envío automático por Messenger.** La cola queda en `pending` para aprobación manual.
- **Ley 18.331**: del vendedor solo `seller_id` y conteo de publicaciones. El payload de detalle
  expone `seller_phone_number` y el nombre — no leerlos ni persistirlos.
- **Rate limiting**: delays aleatorios 8–20s, tope de concurrencia, presupuesto de 100 listings
  por proceso. Cualquier camino nuevo que navegue tiene que pasar por `withPoliteSlot`.
- **Moneda**: `price` y `currency` siempre separados, nunca normalizar al escribir. Se guardan
  `currency_reported` (lo que dice FB) y `currency_resolved` (nuestra lectura) con confianza.
- **Parsers**: preferir el JSON embebido de Relay antes que selectores CSS, y fallar explícito
  y logueado — nunca devolver null en silencio.
- Avanzar de a una fase y parar a confirmar antes de seguir (ver `docs/claude-prompt.md`).

## Cómo verificar sin quemar requests a Facebook

- `npm test` — no toca Facebook.
- `npm run worker:dry` — SÍ toca Facebook (~30 requests, ~55s). Usarlo con criterio, no en loop.

  en vez de re-scrapear.
- No hay Postgres en esta máquina (ni docker/podman). Para probar la persistencia hace falta
  un `DATABASE_URL` (Supabase) o levantar Postgres.
